# How it works

The Windows manager queries HOME and LEANBACK_LAUNCHER activities and stores the selected exact component in device-protected preferences. `HomeOverrideService` watches `TYPE_WINDOW_STATE_CHANGED` and `TYPE_WINDOWS_CHANGED`. It uses the active window root when readable; on MFTR0, a fresh exact Xiaomi Home/FallbackHome window event can stand in when that root is unavailable. Normal Xiaomi Settings pages do not match. It permits at most three target starts and two previous-launcher fallback starts within ten seconds, plus a rolling limit of ten starts per minute. A target is confirmed only after a stable foreground observation. If both targets fail, it disables its own override and leaves Xiaomi Home available.

BootReceiver records a durable boot signal, schedules a persisted one-shot JobScheduler task, and starts a bounded worker on MFTR0. A persisted periodic job is a fallback if a boot broadcast is missed. The worker checks ADB setting and TCP/adbd properties separately, then repairs only the Toolkit Accessibility service when needed. On MFTR0 it may write and read back `adb_enabled` using the one-time WRITE_SECURE_SETTINGS grant, but never calls blueplanet's vendor bridge or restarts adbd. It merges the Accessibility list rather than replacing unrelated services. The recovery budget is four attempts per boot, at least ten seconds apart. No default Home mutation occurs.
